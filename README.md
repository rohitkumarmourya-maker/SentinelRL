# SentinelRL: Budgeted Adaptive Cyber Defence

SentinelRL is an independently written, CPU-runnable reinforcement-learning cyber-range project. It investigates whether a Deep Q-Network (DQN) can make effective inspection, patching, isolation, and decoy-placement decisions in a synthetic enterprise network when the defender has noisy alerts, stochastic lateral movement, and only **six response actions per 48-step episode**.

> **Scope and safety:** SentinelRL is an abstract teaching simulator. It does not connect to real networks, send packets, scan devices, execute exploits, or contain attack code. All compromise events are generated by stochastic transitions across a synthetic graph. Results are simulation benchmarks only, not claims of operational deployment safety.

## Key Algorithmic Improvements (Why and How the Model Was Optimized)

In the initial implementation, standard DQN underperformed hand-coded heuristics because:
1. **The "Sugar-Rush" Reward Trap**: Inspecting an infected host gave an immediate `+1.50` reward, causing the agent to greedily exhaust its 6 response tokens in the first 10 steps, leaving critical assets unisolated late in the episode.
2. **Value Estimation Friction**: A standard MLP struggled to decouple the intrinsic state quality $V(s)$ from individual action advantages $A(s, a)$.
3. **Credit Assignment Lag**: 1-step TD learning was too slow to backpropagate late-game containment rewards across a 48-step sparse trajectory.
4. **Blind Exploration**: Random exploration wasted scarce actions on benign or low-value nodes.

### Enhancements Implemented:
- **Graph-Dueling Double-DQN**:
  - Incorporates a normalized Graph Convolution (GCN) layer ($\hat{A} H W$) that pools threat representations across network edges, allowing high-value assets to anticipate incoming lateral attack vectors before they arrive.
  - Decomposes state evaluation into separate State-Value $V(s)$ and Advantage $A(s, a)$ heads with `LayerNorm` for gradient stability:
    $$Q(s, a) = V(s) + \left(A(s, a) - \frac{1}{|\mathcal{A}_{\text{legal}}|} \sum_{a' \in \mathcal{A}_{\text{legal}}} A(s, a')\right)$$
- **Zero-False-Isolation Safety Shield**:
  - Adds an operational guardrail that suppresses speculative quarantines on unverified clean nodes unless verified by inspection or posterior belief $\ge 0.90$, achieving **$0.000$ false isolations**.
- **Deep Q-Learning from Demonstrations (DQfD)**:
  - Seeds the replay buffer with expert transitions from `AlertResponderPolicy`.
  - Employs a large-margin supervised classification loss on expert transitions to enforce decisive action selection during critical breach moments.
  - Guided $\epsilon$-greedy exploration: samples expert guidance $65\%$ of the time during exploration.
- **Multi-Step ($n=3$) Returns**: Bootstraps targets over 3 steps, linking defensive actions directly to delayed attack containment downstream.
- **Budget-Pacing & Containment Reward Shaping**: Introduces pacing penalties for early budget depletion, dampens myopic inspection bonuses, and penalizes false isolations during training while rewarding timely quarantine of high-value assets ($C \ge 0.8$).
- **Soft Polyak Target Updates**: Smooth target network synchronization ($\tau = 0.005$) preventing destabilizing value oscillations.

## How Actions Work

The discrete action space consists of 25 actions:
- `0`: `WAIT` (costs 0 tokens, always legal)
- `1..6`: `INSPECT` host 0..5 (reveals ground truth compromise state)
- `7..12`: `PATCH` host 0..5 (reduces lateral compromise probability by 84%)
- `13..18`: `ISOLATE` host 0..5 (severs network links, preventing further propagation)
- `19..24`: `DECOY` host 0..5 (reduces compromise probability by 90% and raises diversion alerts)

Actions are constrained by a boolean mask that disallows redundant operations and enforces the hard 6-token response budget.

## Installation & Execution

### 1. Setup Virtual Environment
```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 2. Run Test Suite
```bash
python -m pytest -q
```
All 6 unit tests verify reset/step shapes, deterministic transitions, action masking, budget invariance, and checkpoint serialization.

### 3. Run Full Pipeline
To train across seeds 17, 29, 43, evaluate on 30 held-out scenarios, run sensitivity sweeps, and regenerate plots:
```bash
python run_all.py --episodes 280 --eval-episodes 30
```

To run training only:
```bash
python train.py
```

To run evaluation on existing checkpoints:
```bash
python evaluate.py
```
