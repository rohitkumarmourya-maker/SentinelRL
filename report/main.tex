\noindent\textbf{Abstract.} We study whether a Deep Q-Network (DQN) can make useful defensive decisions in a synthetic enterprise network with noisy alerts, stochastic lateral movement, and only six response actions per episode. The custom environment supports inspection, patching, isolation and decoy deployment. DQN improves over random and patch-priority policies, but not over the strongest hand-coded defenders in this experiment.

\section*{1. Problem and Contribution}
Enterprise defenders must decide which assets to inspect, harden, isolate or use as decoys while incidents evolve and response capacity is limited. The action sequence matters: inspecting a host reveals its status, isolation prevents lateral spread, patching reduces future entry risk, and each intervention consumes one of only six response tokens. Alerts may be missed or false, so the agent acts on uncertain evidence rather than true compromise labels.

RL-based cyber defence and network simulators are established research areas, including CyberBattleSim, MininetGym and recent autonomous-defence reviews [1--3]. SentinelRL claims neither a new RL algorithm nor a new research domain. Its coursework contribution is a six-host POMDP combining a strict response budget, approximate host-belief features, four defensive actions and an attack-rate sensitivity test.

\section*{2. POMDP Formulation}
The underlying state includes hidden compromise flags, host controls, telemetry, beliefs, budget and time. The DQN observes 58 values: nine per host (belief, alert, inspected/confirmed status, vulnerability, criticality, patched, isolated, decoy), plus four global features for budget, time, detections and newly compromised hosts. True compromise flags are hidden.

The 25 discrete actions are wait, inspect $i$, patch $i$, isolate $i$, or deploy a decoy on host $i$ ($i=0,\ldots,5$). A mask excludes unavailable actions; wait is always valid. Each intervention consumes one of six tokens. Episodes last 48 steps. An attacker starts at the gateway or staff laptop and can spread across a fixed six-host graph.

For target host $j$, each compromised neighbour attempts lateral movement with probability
\[
p_j=0.23v_jm_jd_j,\quad m_j=\begin{cases}0.16,&\text{patched},\\1,&\text{otherwise},\end{cases}
\]
Here $v_j$ is vulnerability and $d_j=0.10$ with a decoy, otherwise $1$. Alert sensitivity is 0.55 and false-positive probability 0.08. All values are synthetic; the factorized belief update is approximate.

\section*{3. Reward and Learning}
The reward sums event terms. Here $c_i$ is host criticality; $N_t$ is newly compromised hosts; $D_t$ counts decoy diversions; $A_t,F_t$ are newly reported true/false alerts; $U_t$ is compromised but unisolated hosts; and $C_T$ is critical compromised hosts still unisolated at the horizon:
\begin{align*}
r_t={}&-0.16I_{\rm response}-0.45I_{\rm invalid}\notag\\
&+1.50I_{\rm true\ inspect}-0.18I_{\rm clean\ inspect}\notag\\
&+0.12c_iI_{\rm patch}\notag\\
&+(1.10+0.55c_i)I_{\rm true\ isolate}\notag\\
&-(0.65+0.85c_i)I_{\rm false\ isolate}\notag\\
&+0.08v_iI_{\rm decoy}-\sum_{i\in N_t}(2+4c_i)+0.75D_t\notag\\
&+0.10A_t-0.06F_t-0.16\sum_{i\in U_t}c_i\notag\\
&-1.4\sum_{i\in C_T}1.
\end{align*}
Action-specific terms use the acted-on host $i$. Coefficients are design weights, not calibrated monetary costs. Operational outcomes are reported separately from shaped return to reduce reward-hacking risk.

The CPU DQN uses a 58--128--128--25 MLP, replay buffer, target network, masked epsilon-greedy exploration, Adam, Huber loss and gradient clipping. Three training seeds (17, 29, 43) run for 280 episodes each. Baselines are Random Legal, Patch Priority, Alert Responder and Threshold Defense. Each baseline is tested on 30 held-out scenarios; each DQN checkpoint uses the same scenarios. DQN metrics are averaged across checkpoints within each scenario before summary statistics.

\section*{5. Interpretation}
DQN's mean critical-compromise count is 0.644 (scenario-level standard deviation 0.748); Alert Responder has 0.233 (0.504) and Threshold Defense 0.400 (0.855). DQN reduces mean detection delay in this run but leaves more active compromises by the episode horizon. The results show that a learned policy is not automatically superior to a carefully designed heuristic.

\section*{6. Attack-Rate Sensitivity}
The trained agents were evaluated without retraining at attack probabilities 0.18, 0.23 and 0.28, with alert rates and budget fixed. Twenty scenarios were used per condition. At probability 0.23, mean critical compromises were 0.483 for DQN, 0.050 for Alert Responder and 0.250 for Threshold Defense. At 0.28 they were 0.567, 0.400 and 0.500 respectively. DQN is not best across all conditions; this sensitivity experiment is descriptive and small.

\section*{7. Limitations and Conclusion}
The topology, attacker, alerts, criticalities and response budget are synthetic; the belief estimator is approximate; and the study has limited seeds and evaluation scenarios. We model no real packets, malware, operating systems, patch latency, alert correlation or adaptive human attacker. Results do not validate deployment. The supported conclusion is narrower: DQN learns a policy stronger than random and patch-only baselines, while transparent heuristic defenders remain better on aggregate return and containment. Future work should examine recurrent policies, richer telemetry and larger scenario sets.

\section*{Reproducibility and Safety}
Code, checkpoints, tests, per-episode CSVs and plots are included. Run \texttt{python -m pip install -r requirements.txt}, \texttt{python -m pytest -q}, then \texttt{python run\_all.py --episodes 280 --eval-episodes 30}. This CPU-only simulator does not connect to real systems and cannot validate operational cybersecurity.
