# Submission checklist

- [ ] Check the complete FCFS idea sheet and obtain approval; screenshots alone cannot prove no other entry overlaps.
- [ ] Submit the ≤50-word abstract in `IDEA_SUBMISSION.md` only after confirming the topic is unclaimed.
- [ ] Inspect and run all source code; do not submit a project you cannot explain.
- [ ] Run `python -m pytest -q` and keep the actual result.
- [ ] Publish the repository to your own GitHub account; replace `[GITHUB URL]` in `report/main.tex` with the real URL.
- [ ] Add correct team-member names and identifiers in the report.
- [ ] Create truthful incremental commits as you review, understand, fix and document the code. Do not fabricate history or dates.
- [ ] If private, grant access to the course staff accounts listed in the assignment PDF.
- [ ] Recompile the LaTeX PDF and verify main content is exactly two pages before the references page.
- [ ] Review figures and ensure they correspond to the final CSVs.
- [ ] Be ready to explain why the trained DQN does not beat the two strongest heuristic baselines in this run.
- [ ] Make no real-world deployment claims.
