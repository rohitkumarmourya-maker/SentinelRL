# Common-environment comparator protocol (development stage)

Every policy acts in the exact corrected six-host POMDP. `src/environment.py` is byte-identical to the prior corrected delivery: no transition, sensor, horizon, budget or reward coefficient changes. The original GitHub reproduction remains a separate historical experiment and its raw returns are never compared directly to this environment.

## Inputs and lawful original adapter

All policies receive the same public 56D observations and actual legality mask. The flagship and adapted original policies may causally filter their own public observations/actions using the same exact 64-state infection posterior; no latent simulator state or hidden reward-derived count enters that filter. It supplies available infection marginals fairly to the original controllers.

Original 58D host entries are `[posterior marginal,current alert,ever explicitly inspected,explicitly confirmed positive,vulnerability,criticality,patched,isolated,decoy]`. Globals are normalized budget/time, number of explicitly positive diagnoses divided by 6, and **0 for the unavailable privileged new-compromise count**. Inspections remain stale after hidden infections. The old inspection-availability convention, never-inspected OR current-alert, is derived only from public history and intersected with true legality; no latent reset is restored. Uniform random uses all actual legal actions. Its policy RNG seed is generated by `SeedSequence([scenario_seed,0x53454E54]).generate_state(1)[0]`, domain-separated from environmental randomness. The initial validation random row used a shared integer seed and is preserved as a superseded stream choice; only that row was rerun into `validation/random_independent_stream_v2/`. Original GitHub reproduction remains unchanged.

## Recorded comparator families

| Family | Definition |
|---|---|
| Previous corrected DDQN / no-memory / tabular | Exact prior three-seed checkpoints, original 56D observation and original architecture/encoding; saved source/parameter identity verified against immutable v2 archive |
| Original alert / threshold / patch rules | Original implementation code, lawful 58D adapter and public inspection affordance |
| Original random legal | Original uniform legal-action implementation with independent policy randomness |
| Original full / no-stealth transferred checkpoints | Strictly loaded original three-seed graph-dueling checkpoints and original prior/shield; lawful 58D adapter; clearly **domain transfer**, not retraining |
| Faithful graph+prior/shield retrained | Same original graph-dueling architecture and strategic prior/shield; lawful 58D features, corrected reward, no hidden training shaping, no teacher/demonstration loss; matched RL budget |
| Pure graph-dueling retrained | Same original graph-dueling network, both prior and posthoc shield disabled; learned Q alone ranks actual legal actions; lawful 58D features and matched RL budget |
| Tuned belief-threshold diagnostic | Separate new handcrafted control selected among 40 predeclared configurations on 200 validation scenarios; distinct from the original threshold rule and never a flagship teacher |
| No-op | Wait-only task-difficulty control |

With the unavailable privileged channel fixed to 0, the original transferred full and no-stealth policies are expected to coincide. This is disclosed rather than counted as evidence that the missing feature was harmless in the original environment.

The pure graph retrain uses the v1 flagship training contract: gamma 1, 3-step returns, batch 128, replay100,000, Adam .0005, Huber beta 5, target copy every 500 updates, gradient norm clip 10, epsilon 1→.02 over 300,000 actual environmental steps. Twenty thousand episodes/seed correspond to 960,000 actual environment transitions. Exact forced-WAIT suffix compression folds actual remaining rewards into the preceding transition with the correct duration discount; all 48 environment steps still execute. Network hidden 128 and the original graph/dueling structure are preserved. No new architecture or reward is introduced for these comparators. The faithful prior/shield comparator was rerun with the original numeric `train_every=8` parameter after a documented expensive development trial showed flat validation. In this shared trainer the parameter divides decision-transition updates, so it is not an exact reproduction of the historical environment-step cadence. Actual updates/compute are reported rather than called equal. The pure learned graph remains at `train_every=1`. Both rerun seeds receive the full 20,000-episode interaction budget.

## Development, selection and fresh final test

Old 300000/400000 scenarios are development data. Current validation uses 200 scenarios `600000+101*i`, i=0..199. The tuned diagnostic grid includes isolation thresholds .5/.65/.8/.9/.98, inspection thresholds disabled/.2/.4/.6 and optional preventive patching, 40 combinations total. Every configuration/result is retained; maximum validation mean return selects the control.

Final scenarios start at `900000+103*i`. They are sealed: `benchmark.py --split final` requires a parent authorization file matching the exact frozen protocol bytes, model hashes, unchanged environment and scenario count. Proposed final count is 1,000 with five new training seeds 17/29/43/71/89; configuration/count will be frozen before authorization. No final outcomes have been generated during development.

Old pretrained families retain their three actual independent checkpoints. They are never cycled into fake five-run samples. The planned uncertainty calculation independently resamples the new and comparator training-seed axes while sharing scenario draws, preserving pairing and allowing unequal seed counts. A deterministic control has one row. Primary return comparisons use 20,000 crossed-bootstrap replicates and Bonferroni intervals at alpha .05/K over the closed, prespecified comparator set. Individual fixed old checkpoints can be included as additional comparisons if preregistered. Secondary metrics remain honest exploratory outcomes; zero false-isolation controls make strict wins on every metric impossible.

Per-run immutable source snapshots are verified and imported for new checkpoints. Existing snapshot hashes/parameter checks are retained, so adding unrelated modules or developing later candidates cannot silently change a recorded policy's runtime.
